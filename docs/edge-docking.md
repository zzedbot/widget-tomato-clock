# 边缘停靠行为设计

> 状态：已实现  
> 坐标单位：Electron/Windows 设备无关像素（DIP）

## 1. 目标

当番茄钟挂件靠近或越过当前显示器的可用区域边缘时，自动收起为一个小番茄，减少对桌面操作的遮挡。鼠标移入番茄后展开完整挂件，移出后再次收起；用户把展开后的挂件拖离边缘即可解除停靠。

## 2. 边缘判断

判断对象是**窗口四条边**与**当前显示器可用区域四条边**之间的关系，而不是窗口中心点。

四个有符号间距定义如下：

```text
leftGap   = window.left - workArea.left
rightGap  = workArea.right - window.right
topGap    = window.top - workArea.top
bottomGap = workArea.bottom - window.bottom
```

间距含义：

- 大于 0：窗口边缘仍在屏幕内部；
- 等于 0：窗口边缘与屏幕边缘接触；
- 小于 0：窗口边缘已经越过屏幕边缘。

任意一个间距满足 `gap ≤ 32 DIP` 时，该边成为停靠候选。因此：

- 距离边缘 32 DIP 内会停靠；
- 正好接触边缘会停靠；
- 部分或大幅越过边缘仍会停靠；
- 不使用绝对值，避免越界越多反而无法停靠的问题。

## 3. 多边与角落处理

窗口靠近角落时可能同时命中两条边：

1. 如果已经越界，选择负值更小、即越界更深的边；
2. 如果仍在屏幕内部，选择正值最小、即距离最近的边；
3. 完全相同的情况下按左、右、上、下的稳定顺序选择，避免反复跳边。

收起后的番茄会被限制在 `workArea` 内，不能进入任务栏，也不能在与停靠边垂直的方向上超出可见区域。

## 4. 状态与交互

```text
浮动窗口
  └─ 拖到边缘或越界并松开鼠标 → 边缘收起
       └─ 鼠标移入 → 边缘展开
            ├─ 鼠标移出 420ms → 边缘收起
            └─ 手动拖离边缘 → 浮动窗口
```

- **浮动窗口**：普通主挂件，可自由拖动；
- **边缘收起**：约 62 × 62 DIP，只显示番茄和当前状态点；左右停靠时其 top 与收起前窗口 top 对齐，上下停靠时其 left 与收起前窗口 left 对齐；
- **边缘展开**：恢复主挂件尺寸，并始终向屏幕内部展开；
- **迷你计时**：开始专注后的普通迷你模式；若窗口已经停靠边缘，则优先保留边缘停靠逻辑。

用户按住鼠标拖动时只更新窗口位置，不执行边缘收起。Windows 发出拖动结束事件（鼠标松开）后，程序才根据最终位置判断是否停靠；因此窗口不会在鼠标仍按下时从指针下突然变成番茄。

程序主动调整窗口大小时会暂时抑制边缘检测，避免展开后立即再次收起；用户手动拖动会取消该抑制。

已停靠展开态虽然仍与屏幕边缘相接，但不会被移动事件立刻再次收起；只有鼠标离开才触发延迟回收。这样可以避免展开与收起反复抖动。

回收定时器到期时会再次读取系统鼠标坐标。只有指针确实位于展开窗口边界之外才执行收起，从而过滤窗口缩放、视图切换产生的瞬时 `mouseleave`。

## 5. 动画

- 原生窗口边界一次性调整，避免 Windows 逐帧缩放窗口产生卡顿；
- 可见内容使用约 220–240ms 的 GPU 合成层 ease-out 动画；
- 番茄收起态使用淡入、缩放和极轻旋转，主挂件展开使用淡入缩放；
- 悬停番茄时仅让状态点轻微呼吸，不使用持续的大幅运动；
- 动画不参与停靠判定，动画期间的窗口移动事件会被忽略；
- Windows 启用“减少动画”时，原生窗口过渡和 CSS 动效均近似即时完成。

## 6. 多显示器与任务栏

- 使用与窗口重叠面积最大的显示器作为当前显示器；
- 使用显示器的 `workArea`，而不是完整物理边界，因此会避开任务栏；
- 每次移动都重新获取显示器，支持不同分辨率、不同 DPI 和显示器排列；
- 展开与收起后的坐标均会限制在当前 `workArea` 内。
