# 番茄钟 × 待办完整功能设计

> 阶段：完整产品设计，等待确认后实施

## 1. 设计目标

待办负责回答“现在做什么”，番茄钟负责回答“这段时间怎样被切分和记录”。系统必须形成完整闭环：创建待办 → 加入本轮 → 专注执行 → Punch 完成 → 在已办中追溯 → 必要时恢复为待办。

主挂件仍以计时为第一视觉层级；完整管理能力放在独立待办面板中，避免挂件持续遮挡屏幕。

## 2. 核心概念

### 2.1 长期待办

- 通常跨越一天以上，例如“完成新版产品方案”；
- 可以作为若干短期待办的父目标；
- 显示直接投入、子待办汇总投入、完成次数和未完成子项数；
- 一个专注时刻只有一个当前长期目标。

### 2.2 短期待办

- 通常在几分钟到数小时内完成；
- 可以归属于一个长期待办，也可以独立存在；
- 可以加入本轮队列，并在运行中切换当前执行项。

### 2.3 三种互不混淆的状态

待办的永久状态只有“待办”和“已办”；“本轮已选”和“正在执行”属于番茄会话状态，不写进永久状态。

| 维度 | 可选值 | 含义 |
| --- | --- | --- |
| 永久状态 | 待办 / 已办 | 是否已被 Punch 完成 |
| 本轮状态 | 未加入 / 已加入 | 是否属于当前番茄的任务集合 |
| 执行状态 | 非当前 / 当前执行 | 当前时间片直接记到哪一项 |

因此，暂停番茄不会把待办变成已办；退出本轮也不会删除待办；只有 Punch 才会进入已办。

## 3. 生命周期

```text
新建
  ↓
待办库 ──加入本轮──→ 本轮已选 ──开始/切换──→ 当前执行
  ↑                         │                     │
  │                         └────取消本轮─────────┘
  │                                               │
  └────恢复为待办──── 已办 ←────── Punch ─────────┘
```

### 3.1 Punch

Punch 是主动确认完成，不等同于番茄结束：

1. 关闭当前时间片；
2. 写入不可变的 Punch 记录；
3. 将待办设为已办并从本轮移除；
4. 队列仍有项目时自动切换到下一项；
5. 队列为空时番茄继续，但明确提示“添加待办继续记录”或“结束本轮”；
6. 显示约 5 秒反馈，并提供“撤销 Punch”。

### 3.2 撤销 Punch

用于刚刚误操作：

- 仅对最新一次 Punch 在短时间内提供；
- 撤销该次完成事件，恢复此前的本轮选择与当前执行关系；
- 不新增一次“恢复历史”，避免误操作污染统计。

### 3.3 已办恢复为待办

用于确实需要重新处理，而非撤销误操作：

- 保留原待办 ID、历史时间片和历次 Punch，不删除过去成果；
- 新增一条 Reopen 事件并开启新的完成周期；
- 状态恢复为待办，`completedAt` 清空；
- 默认只恢复到待办库，不自动加入本轮；
- 专注运行中提供两个明确动作：“恢复为待办”和“恢复并加入本轮”；
- “恢复并加入本轮”只加入队列，不强行打断当前执行项；队列为空时可自动成为当前执行项；
- 恢复长期待办时，不自动恢复其已办子项；用户可在确认面板中逐项勾选需要恢复的子项。

## 4. 信息架构

完整待办面板使用两个一级页签：

### 4.1 待办

- 顶部：搜索、新建按钮、本轮已选数量；
- 本轮区域：所有已选项、排序、当前执行高亮；
- 长期待办：目标名称、累计专注、未完成子项、当前目标标记；
- 短期待办：所属长期目标、累计专注、本轮选择状态；
- 筛选：全部 / 长期 / 短期；
- 行操作：加入或移出本轮、设为当前、Punch、编辑、归属调整、移至归档。

### 4.2 已办

- 默认按 Punch 日期分组：今天、昨天、本周、更早；
- 支持全部 / 长期 / 短期筛选与关键字搜索；
- 每行显示：标题、类型、完成时间、本次周期耗时、历史总耗时、完成次数；
- 主操作：“恢复为待办”；
- 次操作：“查看记录”；
- 空状态说明 Punch 后的任务会出现在这里。

### 4.3 待办详情

从待办或已办列表进入详情抽屉：

- 标题、类型、所属长期目标和当前状态；
- 历史总专注时间、当前周期时间、完成次数；
- 时间线：创建、加入本轮、时间片、Punch、撤销、恢复；
- 时间片按番茄会话分组，可追溯开始、结束和直接归属；
- 已办状态下提供恢复操作，待办状态下提供 Punch。

## 5. 各挂件形态

### 5.1 主挂件

- 展示当前长期目标、当前执行项、当前项累计时间和 Punch；
- 展示“本轮待办 N 项”的紧凑横向队列，当前项高亮；
- 点击队列项立即切换执行归属并切开时间片；
- 管理按钮进入完整待办面板；
- Punch 后显示成功反馈和撤销入口。

### 5.2 迷你挂件

- 展示倒计时、当前执行项和“本轮 N 项”；
- 完整清单通过悬停提示或展开主挂件查看；
- 不放 Punch，避免误触。

### 5.3 停靠番茄

- 保持纯番茄形态；
- 鼠标移入展开后恢复主挂件信息；
- 待办面板打开时退出停靠状态。

## 6. 关键交互规则

### 6.1 开始番茄

- 专注阶段未选择待办时，点击开始会打开待办面板；
- 至少选择一项后才能开始；
- 多选时必须有一个当前执行项，默认优先第一个短期待办，其次第一个长期待办；
- 休息阶段不要求选择待办，也不累计待办时间。

### 6.2 运行中变更

- 新建短期待办：自动加入本轮；队列为空时自动开始归属；
- 切换执行项：关闭旧时间片并打开新时间片，不重置倒计时；
- 更换长期目标：关闭旧上下文时间片并创建新上下文时间片；
- 移出当前执行项：自动选择队列下一项，并切开时间片；
- Punch 非当前项：完成并记录其历史耗时，但不改变当前时间片。

### 6.3 Punch 长期待办

如存在未完成短待办，弹出确认面板，提供：

1. 完成长期目标，子项保留为独立待办；
2. 完成长期目标，并选择需要一起 Punch 的子项；
3. 取消。

绝不自动删除子项。

### 6.4 恢复长期待办

- 恢复长期目标本身；
- 展示历史子项，允许勾选恢复其中的已办子项；
- 尚未完成的独立子项不会被自动重新挂接，除非用户确认。

## 7. 时间与历史模型

### 7.1 单一归属原则

- 每个时间片只有一个 `todoId`，避免同一分钟重复直接计入多个待办；
- 时间片同时保存当时的 `longTodoId` 上下文；
- 长期目标的汇总时间由相关时间片计算，不另建重复时间；
- 暂停和休息时间不计入。

### 7.2 数据实体

- `Todo`：类型、标题、永久状态、父长期目标、创建与当前完成时间；
- `FocusSession`：番茄会话、开始结束时间及本轮队列快照；
- `TimeSegment`：会话、直接待办、长期上下文、开始结束时间；
- `CompletionCycle`：一次“待办 → Punch → 可能恢复”的周期；
- `PunchRecord`：完成时间、本周期直接耗时、长期汇总耗时、来源会话；
- `TodoEvent`：创建、编辑、加入本轮、移出本轮、Punch、撤销、恢复等审计事件。

时间片与历史事件关闭后不可原地改写。恢复为待办只开启新周期，旧记录仍可追溯。

### 7.3 展示口径

- “本轮”：当前番茄会话内的已关闭和开放时间片；
- “本次周期”：上次恢复或创建之后累计的时间；
- “历史总计”：该待办所有周期的直接耗时；
- 长期目标“汇总”：其直接耗时与作为长期上下文的短待办时间片之和；
- 已办列表默认显示本次周期耗时，同时保留历史总计。

## 8. 编辑、归档与删除

- 编辑标题或归属不改写历史时间片中的名称快照与上下文；
- “归档”用于隐藏不再计划处理的待办，可从归档页恢复；
- 有时间片或 Punch 历史的待办不提供普通硬删除，只允许归档；
- 无任何历史的新建待办可以永久删除，但必须二次确认；
- 已办不是归档：已办用于成果追溯，归档用于清理待办库。

## 9. 空状态与反馈

- 待办为空：“先创建一个要推进的目标”；
- 本轮为空：“至少选择 1 项才能开始专注”；
- 已办为空：“Punch 完成的任务会保留在这里”；
- Punch 后队列为空：“本轮暂无计时归属”，提供“添加待办”和“结束本轮”；
- 恢复成功：“已恢复为待办”，运行中追加“加入本轮”快捷动作；
- 所有破坏性动作均说明对历史记录的影响。

## 10. 键盘与可访问性

- 每个图标按钮有可读名称；
- 当前执行项使用 `aria-current`，选中状态使用 `aria-pressed` 或原生复选框；
- Tab 顺序遵循页签 → 搜索/新建 → 列表 → 底部主操作；
- Enter 打开或确认，Space 切换选择，Escape 关闭抽屉或弹窗；
- 动画响应 `prefers-reduced-motion`。

## 11. 验收清单

- 未选择待办不能开始专注；
- 开始后可以看到并切换本轮全部待办；
- 多选不会造成直接耗时重复计算；
- 运行中新增、移出、切换任务不影响番茄倒计时；
- 更换长期目标不会丢失切换前耗时；
- Punch 后任务进入已办，记录完成时间、耗时和会话；
- Punch 后可短时撤销；
- 已办可恢复为待办，旧 Punch 与时间片仍然存在；
- 同一待办可以经历多次完成周期，每次记录均可区分；
- 恢复长期目标不会误恢复或删除子项；
- 暂停和休息期间不产生待办耗时；
- 列表为空、队列为空和历史为空均有明确下一步；
- 主挂件尺寸不因完整待办库而增大。

## 12. 推荐实施顺序

1. 补齐状态模型：完成周期、事件、撤销和恢复；
2. 增加待办/已办双页签与筛选；
3. 实现已办详情、恢复为待办及恢复并加入本轮；
4. 实现 Punch 撤销和长期子项确认；
5. 增加编辑、归档、搜索与完整空状态；
6. 补齐账本迁移、单元测试和 Electron 端到端测试。
